`aws-rpms`, with repository metadata generated by the independently verified
`createrepo_c` public preparation. It also carries `aws-guest-install.sh`,
`aws-transaction-guard.py`, `s3-responder.py`, and the exact stripped adapter.
No virtual NIC or network-enabled installation is permitted.

The installer checks the fixed complete payload manifest hash, all71 payload
hashes and all signatures against only the approved Fedora44 key. DNF resolves
`awscli2` against the actual installed guest RPM database and stores, rather
than runs, its transaction. The guard accepts only version1.0 with new Install
actions from that local repository, exact NEVRA/payload joins, no unknown
fields or duplicates, and no already-installed package name. It does not
implement dependency resolution. The actual stored DNF format was checked
against upstream5.4.2.0 `transaction_sr.cpp` and the retained public QEMU plan.

The selected new RPMs undergo `rpm --test -ivh` before exact DNF replay, without
skip/ignore/replace options. The installed set must remain unchanged after
planning/testing and equal precisely its prior set plus the approved new rows
after installation. Systemd executable/control/credential-tool hashes must
also remain identical. This protects the qualified systemd/kernel/core package
versions; it does not assert that signed package scripts have no effects in
the disposable guest. Unsupported guest tooling/solver results deny rather
than selecting a different package closure.
